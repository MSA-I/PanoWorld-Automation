## 1. מטרת האוטומציה

OmniRoute יתכנן וינהל את כל שרשרת WP0–WP6 מראש, אך יבצע אותה כמחזורי עבודה תחומים וברי־שחזור. Anthropic היא יעד מועדף כאשר היא זמינה ומתאימה; כאשר אינה זמינה, OmniRoute ממשיך עם חלופה כשירה ומתועדת. שום fallback אינו משנה scope, contract, acceptance או security.

## 2. התאמת התוכנית למסמכים הקיימים

מסמכי 01–07 מתארים pipeline מוצרי רחב של 13 שלבים, לרבות שלבים עתידיים של Blender, rendering ו-H200. שרשרת WP0–WP6 הנוכחית היא **מסלול remediation מקומי ומוגבל** עבור recognition/contracts/activation decision; היא אינה היתר לבצע את כל 13 שלבי המוצר.

| WP נוכחי | משמעות | מיפוי למסמכי 01/03 | גבול |
|---|---|---|---|
| WP0 | הכרעות, ADR, CPU feasibility וחבילת evidence | הכנה ל־Intake/Parsing, Gates G0–G1 | local-only; ללא route activation |
| WP1 | נעילת corpus, זכויות, truth ו-evaluator | תשתית בדיקה לשלב 2 Parsing | ללא רכישת corpus ברשת |
| WP2 | contracts additive ו-run lifecycle | שלב 0 Contracts + חוזי שלב 2 | new-runs-only; תאימות היסטורית |

שלבי Geometry, Cameras, Rendering, Style, Source Panorama, H200, QA סופי ו-Dashboard אינם מבוצעים בשרשרת זו אלא אם הם מופיעים במפורש כ-evidence/mock מקומי שאינו מפעיל מוצר. G7/G8 ו-PART 2 נשארים `DEFERRED`.

## 3. ארכיטקטורת הבקרה

```text
Moshe activation approval
        ↓
Omni Controller (panoworld profile via OmniRoute)
        ↓
Policy preflight → canonical packet hash → board reconciliation
        ↓
WP0 → WP1 → WP2 → WP3 → WP4 → WP5 → WP6
 │      │     │     │     │     │     │
 └─ plan/implement/test/review/rework/verify/checkpoint/handoff
        ↓
WP6 decision packet → mandatory Moshe activation decision
```

### רכיבי הבקרה

1. **Omni Controller** — קורא state, בוחר agent/model, מנהל dependencies ומיישם את מטריצת האישורים.
2. **Kanban dispatcher** — מתחיל רק כרטיסים eligible; אינו מפרש אישורים.
3. **Policy evaluator** — מסווג כל פעולה `AUTO`, ‏`CONDITIONAL` או `HUMAN_REQUIRED`.
4. **Evidence binder** — מקשר tests/review/run report ל-checkpoint המדויק.
5. **Circuit breaker** — עד שלושה retries טכניים; failures מהותיים נחסמים.
6. **Read-only observer** — שינויי סטטוס מיידיים ו-heartbeat כל 15 דקות; אינו משנה לוח.

## 5. תבנית אוטומציה מחייבת לכל WP

כל WP ייוצג כתת־גרף פנימי:

```text
WPn-PREFLIGHT
→ WPn-PLAN-CHECK
→ WPn-IMPLEMENT
→ WPn-TEST
→ WPn-REVIEW
→ WPn-REWORK (אם נדרש)
→ WPn-VERIFY
→ WPn-CHECKPOINT
→ WPn-HANDOFF
→ WPn-GATE
```

- Planning, implementation ו-review הם sessions נפרדים.
- review ראשון הוא read-only.
- rework יוצר task/run חדש ואינו משנה את דוח המבקר.
- ה־gate בודק evidence, לא ניסוח של agent.
- כל child דינמי מקבל subscription/observer coverage.

## 6. WP0 — הכרעות, ADR ו-CPU feasibility

### מטרה

לסגור את החלטות WP0, לקבע גבולות וראיות, ולייצר feasibility verdict אמין בלי להפעיל route.

### Agents ו-routing

- Planner/Controller: OmniRoute, reasoning מתקדם.
- Spatial designer: Anthropic Opus אם זמין; אחרת חלופה spatial מתקדמת דרך OmniRoute עם `FALLBACK_REVIEW_REQUIRED`.
- Evidence implementer: coding model דרך OmniRoute.
- Reviewer: agent/session שונה, עדיפות לספק שונה.

### פעולות

1. לקרוא את checkpoint והחלטות משה; לנעול scope ב-manifest.
2. לקשר את WP0-FX1 כחבילת evidence ולא כ-WP חדש.
3. לאמת rights/provenance, truth עצמאי ושני scale anchors.
4. להריץ protocol CPU דטרמיניסטי על fixtures מאושרים בלבד.
5. למדוד accuracy/yield/runtime/memory/determinism או לסמן `NOT_EVALUABLE` עם סיבה.
6. לעדכן ADR, U-1..U-15, run report ו-evidence index.
7. לבצע review עצמאי של checkpoint מדויק ולתקן findings תחומים.

### Tests/evidence

- hash replay של fixture/truth/anchors.
- targeted tests + full suite בסביבה המאושרת.
- negative tests ל-manifest לא אמין, anchor חסר ו-truth תלוי recognizer.
- runtime/model identity evidence.

### Auto-recovery

429 של Anthropic → המשך דרך OmniRoute עם reviewer חלופי כשיר. אין להמתין ל-Anthropic רק כדי לבצע עבודה הפיכה. אם אין reviewer עצמאי כשיר בכלל, closure נחסם אך artifacts נשמרים.

### Gate יציאה

- WP0 evidence עקבי ו-hash-bound.
- אין CRITICAL/MAJOR פתוח.
- feasibility verdict אינו מנופח.
- WP1 scope כבר נמצא ב-packet המאושר.
- אין activation.

## 13. אוטומציות רוחביות

### Model router

- probe לפני task קריטי.
- Anthropic preferred; OmniRoute fallback.
- actual model/provider/effort נשמרים.
- fallback ל-spatial critical מסמן review משלים, לא threshold חלש.

### Test controller

- commands allowlisted לכל WP.
- RED evidence נשמר לפני GREEN.
- full suite אינו מוחק evidence קודם.
- flaky retry מוגבל ומסומן; deterministic failure נחסם.

### Review controller

- author/reviewer sessions נפרדים.
- exact checkpoint + diff + plan + evidence נמסרים למבקר.
- verdict schema: `APPROVE`, ‏`APPROVE_WITH_FIXES`, ‏`NEEDS_REWORK`, ‏`BLOCKED`.
- findings מקבלים IDs יציבים ונסגרים ב-rework task חדש.

### State reconciler

בסיום כל WP מעדכן באותו checkpoint:

- Kanban — execution/ownership/live status.
- `PROJECT-STATE.yaml` — state קנוני של המוצר וה־PLANs.
- Git checkpoint — גרסת הקוד.
- evidence/run report/handoff — הוכחת ביצוע.
- `docs/PROGRESS.md` — תצוגה נגזרת, לא מקור סמכות עצמאי.
- open decisions/ADRs כאשר רלוונטי.

בסתירה, evidence וה-checkpoint גוברים לצורך gate; Kanban ו-PROGRESS מתוקנים ואינם משמשים להכשיר checkpoint חסר.

### חוזי checkpoint, handoff ו-blocker

כל handoff הוא append-only וכולל `HANDOFF_ID`, producer/consumer, ‏WP/PLAN, checkpoint SHA, artifacts עם schema/version/hash, tests/evidence טריים, assumptions, boundaries, dependencies, blockers, rollback, next allowed action, approval status ו-requested/actual model/fallback. ה-consumer מאמת את הכול לפני קבלה. יש להבחין בין `PRODUCER_VERIFIED`, ‏`REVIEW_APPROVED`, ‏`MERGED_LOCAL`, ‏`PUSHED` ו־`CONSUMER_ACCEPTED`.

כל blocker כולל class/severity/owner, command/input, expected/actual, evidence, root cause, affected stage, retries, last checkpoint, rollback, next action, exit criteria, `AUTO_RECOVERY_ALLOWED` ו־`HUMAN_ACTION_REQUIRED`. `RESOLVED` מחייב verification טרי לפני resume.

Evidence מתבטל לאחר שינוי רלוונטי בקוד/contract/lockfile, rebase/merge שמשנה את העץ הנבדק או שינוי סביבת ביצוע מהותי. פקודת הבדיקה וה-environment נשמרים באופן קנוני בכל checkpoint.

### Observer

- קורא board כל חמש דקות.
- שולח מיד בשינוי משמעותי.
- heartbeat כל 15 דקות בזמן פעילות.
- שקט כאשר אין שינוי ואין heartbeat due.
- אינו unblocks, dispatches או מפרש אישור.

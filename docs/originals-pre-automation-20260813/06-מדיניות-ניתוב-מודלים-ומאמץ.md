# מדיניות ניתוב מודלים, ספקים ו-Effort

## סטטוס וסמכות
- Policy ID: `MODEL-ROUTING-v1`
- תחולה: כל PLAN, agent, review ו-run בפרויקט PanoWorld Automation.
- מסמך זה הוא המקור הסמכותי לניתוב מודלים. תוכנית ספציפית רשאית להחמיר, אך אינה רשאית להחליף מודל קריטי ללא רישום החלטה.

## הנחת יסוד שנקבעה לפרויקט
במשימות תלת־ממד, Blender, גאומטריה מרחבית, מצלמות, extrinsics, depth וניתוח עקביות בין מבטים, **Anthropic Opus 5 הוא ברירת המחדל ומועדף על Fable 5**. זו החלטת routing המבוססת על ניסיון המשתמש. Fable לא ישמש כברירת מחדל למשימות 3D קריטיות.

אפשר להשתמש במודלים של Anthropic או OpenAI. הבחירה נעשית לפי סוג העבודה, לא לפי נאמנות לספק אחד.

## המודלים הזמינים במדיניות

### Anthropic
- `Fable 5` — תזמור ארוך, סינתזה רחבה ותכנון קמפיין.
- `Opus 5` — חשיבה תלת־ממדית, spatial reasoning, Blender, geometry ו-visual review מורכב.
- `Sonnet 5` — מימוש שגרתי, בדיקות, adapters ותיעוד טכני.
- `Haiku 4.5` — סיכומים, triage ועדכוני state מכניים בלבד.

### OpenAI
- `OpenAI GPT-5.6` — reasoning, תכנון מערכות, contracts, debugging, code review וניתוח multimodal. בסביבה הנוכחית מזהה המודל הפעיל הוא `gpt-5.6-sol`; בעת ריצה יש לרשום את המזהה המדויק שהספק החזיר.
- `OpenAI Codex model — latest approved` — מימוש קוד, terminal workflows, tests, refactors ו-CI. אין לנחש שם גרסה; יש לנעול ב-PLAN את המזהה שמופיע בפועל בסביבה.

## סולם Effort מנורמל
הספקים אינם חייבים להשתמש באותם שמות. במסמכי הפרויקט משתמשים בסולם הבא:

| רמה | משמעות | שימוש |
|---|---|---|
| `MEDIUM` | עבודה ברורה ומקומית | סיכומים, docs ועדכוני state |
| `HIGH` | מימוש ובדיקה רגילים | code, tests, adapters |
| `EXTRA` | reasoning עמוק ורב־קבצים | architecture, debugging קשה, visual QA |
| `MAX` | הכרעה קריטית ויקרה | 3D design, gate סופי, migration/remote safety |

בעת הפעלה:
- Anthropic: לבחור High/Extra/Max בהתאם לטבלה.
- OpenAI: למפות ל-reasoning effort הקרוב ביותר שהמודל תומך בו. אם אין `EXTRA`, להשתמש ב-`high` או `xhigh` בהתאם לממשק; אם אין `MAX`, להשתמש ברמה הגבוהה ביותר.
- חובה לרשום ב-run report גם את הערך המנורמל וגם את הערך שנשלח בפועל לספק.

## כללי ניתוב מחייבים
1. כל סוכן מקבל `PROVIDER`, `MODEL`, `EFFORT`, `THINKING`, `MODEL_REASON` ו-`FALLBACK` לפני תחילת עבודה.
2. אין החלפה שקטה של מודל. fallback נרשם ב-state וב-run report.
3. משימות 3D קריטיות מתחילות ב-Opus 5, לא ב-Fable.
4. implementation שגרתי נשלח ל-OpenAI Codex/GPT-5.6 או Sonnet 5; אין לבזבז Opus/Fable על שינוי מכני.
5. review קריטי יהיה ככל האפשר cross-provider: מחבר Anthropic נבדק ב-OpenAI ולהפך.
6. אותו agent/model אינו גם המחבר היחיד וגם המאשר הסופי של artifact קריטי.
7. `MAX` שמור להחלטות קריטיות; אין להפעיל אותו לאורך קמפיין שלם.
8. Haiku אינו רשאי להכריע geometry, security, contracts או Gate.
9. כל output של LLM כפוף ל-tests ולכלים דטרמיניסטיים; מודל חזק אינו ראיה.
10. model routing נמדד אמפירית ב-benchmark של הפרויקט וניתן לעדכון רק דרך ADR.

## חלוקה ספציפית לשלבי ה-3D

### Geometry
- Opus 5 `MAX`: תכנון representation, coordinate systems, topology, booleans ו-acceptance criteria.
- Opus 5 `EXTRA`: מימוש Blender Python כאשר נדרשת הבנה חזותית/מרחבית.
- OpenAI Codex `HIGH`: unit tests, schema adapters, CLI ו-refactor.
- OpenAI GPT-5.6 `EXTRA`: review בלתי תלוי של correctness ו-edge cases.

### Cameras ו-extrinsics
- Opus 5 `MAX`: spatial plan, orientation, overlap ו-doorway visibility.
- OpenAI Codex `HIGH`: אלגוריתם ו-property tests.
- Opus 5 `EXTRA`: inspection של overlays ורינדורי test.

### Depth ו-rendering
- Opus 5 `EXTRA`: coordinate conventions, panoramic projection ו-depth semantics.
- OpenAI Codex `HIGH`: BlenderProc integration, deterministic output ו-tests.
- Opus 5 `MAX`: G4 Render Gate רק כאשר קיימת אי-התאמה מרחבית או ambiguity.

### 3D QA
- Opus 5 `MAX`: review של תמונות, trajectories ו-cross-view geometry.
- OpenAI GPT-5.6 `EXTRA`: בדיקת metrics, logs ו-policy.
- Human: אישור גאומטריה; אין אישור אוטומטי יחיד.

## מתי להשתמש ב-Fable 5
Fable נשאר שימושי, אך לא בתור מומחה 3D:
- תזמור תוכנית ארוכה.
- סינתזה של handoffs רבים.
- roadmap ו-dependency management.
- risk register ו-scope control.
- תכנון סדר הסוכנים.
- review של השלמות התהליך, לא הכרעת geometry.

## מתי להשתמש ב-OpenAI
- כתיבת קוד ו-tests.
- debugging של integrations ותלויות.
- contracts ו-JSON schemas.
- cloud/H200 lifecycle.
- security, retries ו-idempotency.
- independent review של עבודה שנוצרה ב-Anthropic.
- multimodal cross-check כאשר נדרשת דעה שנייה.

## Cross-provider review
משימה קריטית דורשת לפחות שני נתיבים שונים:

```text
Anthropic author → OpenAI reviewer → deterministic tests → gate
```

או:

```text
OpenAI author → Anthropic reviewer → deterministic tests → gate
```

לשלבי 3D:

```text
Opus 5 spatial design
→ OpenAI code/correctness review
→ Blender/test evidence
→ Opus 5 visual gate
→ Human geometry approval
```

## תקציב ושימוש ב-MAX
`MAX` מותר כברירת מחדל רק עבור:
- PLAN חדש שמשנה architecture.
- Geometry representation.
- Camera/extrinsics design.
- unresolved spatial bug.
- H200 security/lifecycle gate.
- final 3D QA.

`MAX` אינו מוצדק עבור:
- formatting.
- status updates.
- boilerplate tests.
- file movement.
- documentation summaries.
- known mechanical refactors.

## Benchmark לפני נעילת המדיניות
ב-PLAN-000/001 יש ליצור evaluation set קטן:
1. floorplan parsing sample.
2. Blender geometry task.
3. camera placement task.
4. depth/extrinsics debugging task.
5. code-only validator task.
6. orchestration/synthesis task.

לכל מודל מודדים:
- correctness מול golden result.
- test pass rate.
- human correction count.
- spatial error count.
- runtime.
- token/cost.
- retry count.

העדפה ל-Opus 5 ב-3D נשארת ברירת המחדל גם לפני benchmark. שינוי שלה מחייב evidence ו-ADR; אין לשנות על בסיס תחושה של סוכן יחיד.

## אישור ושינוי מדיניות

# מקורות וקישורים לפייפליין המוצע

## מקור היעד — PanoWorld

### GitHub
https://github.com/jjrCN/PanoWorld

שימוש בתכנון:
- target input structure.
- `place_image.png`, `place_depth.png`, `place_depth_scale.txt` ו-`extrinsics.txt`.
- map JSON וקשרי viewpoints.
- LRM, 2D generator ו-full pipeline.
- memory benchmarks וסקריפטי training/inference.

### מודלים
https://huggingface.co/JiaJinrang/PanoWorld

נמצאו חמשת רכיבי ברירת המחדל, כולל שני LRM checkpoints, Qwen base, PanoWorld LoRA ו-Lightning LoRA. גודל כולל כ-64GiB.

### נתונים
https://huggingface.co/datasets/JiaJinrang/PanoWorld

כולל RealSee3D evaluation archive ונתוני 3D-FRONT חלקיים. בעת הבדיקה הנתונים המעובדים המלאים לא היו זמינים.

## Floorplan parsing

### CubiCasa5K
https://github.com/CubiCasa/CubiCasa5k
https://arxiv.org/abs/1904.01920

שימוש מוצע:
- segmentation של תוכניות raster.
- rooms, walls, doors, windows וקטגוריות נוספות.

מגבלות:
- stack ישן: Python/PyTorch/CUDA ישנים.
- דורש adapter ומודרניזציה.
- אינו יוצר package של PanoWorld.

### FloorplanTransformation
https://github.com/art-programmer/FloorplanTransformation

מקור raster-to-vector שאליו CubiCasa מפנה. שימושי כ-reference לארכיטקטורת vectorization.

### FloorplanToBlender3d
https://github.com/grebtsew/FloorplanToBlender3d

שימוש מוצע:
- baseline מהיר מתמונת floorplan ל-Blender.
- reference להפקת walls/rooms ול-API.

מגבלות:
- heuristic ורגיש לאיכות התוכנית.
- Docker מבוסס Ubuntu 18.04.
- commit פעילות קוד אחרונה שנמצאה: 2024.
- GPL-3.0; לבדוק השלכה על הפצה.

## 2D floorplan to 3D research

### HouseCrafter
https://github.com/neu-vi/houseCrafter
https://neu-vi.github.io/houseCrafter/
https://arxiv.org/abs/2406.20077

שימוש מוצע:
- reference מתקדם ל-floorplan-conditioned RGBD multi-view generation.
- מפיק RGB, depth ו-camera transformations הקרובים לחוליה שחסרה לפני PanoWorld.

מגבלות:
- דורש layout samples, rendered floor, graph poses ו-wall info — לא JPG גולמי בלבד.
- דורש GPU עם לפחות 24GB VRAM לפי הריפו.
- המחשב הנוכחי אינו מתאים להרצה מעשית.

### Plan2Scene
https://github.com/3dlg-hcvc/plan2scene
https://3dlg-hcvc.github.io/plan2scene/
https://arxiv.org/abs/2106.05375

שימוש מוצע:
- reference ליצירת 3D scene מתוכנית ומספר תמונות.
- texture propagation ו-object placement ideas.

מגבלות:
- דורש תוכנית + סט תמונות/נתוני Rent3D++, לא תמונת style אחת.
- pipeline מורכב ותלויות ישנות.

## Geometry ו-rendering

### Blender Python API
https://docs.blender.org/api/current/

שימוש מוצע:
- יצירת white model דטרמיניסטי.
- walls/floors/ceilings/openings.
- cameras, exports ו-headless rendering.

### Blender
https://www.blender.org/

רכיב geometry המרכזי. מומלץ לבחור גרסת LTS ולנעול אותה.

### BlenderProc
https://github.com/DLR-RM/BlenderProc
https://dlr-rm.github.io/BlenderProc/
https://arxiv.org/abs/1911.01911

שימוש מוצע:
- טעינת scene.
- camera poses.
- RGB, depth, normal ו-segmentation rendering.
- bridge ל-control assets של PanoWorld.

מגבלות:
- GPL-3.0.
- רץ בתוך סביבת Python של Blender.
- נדרשת בדיקת equirectangular output ופורמט depth מדויק.

### Blender MCP
https://github.com/ahujasid/blender-mcp
https://blendermcp.org/

שימוש מוצע:
- inspection ותיקון חריגים בידי סוכן.
- viewport screenshots.
- הפעלת Python בתוך Blender.

מגבלות ובטיחות:
- מאפשר arbitrary Python execution.
- לא להשתמש בו כמנוע batch העיקרי.
- יש לבודד network/permissions ולהגביל commands.

## Workflow ו-agent orchestration
אפשרויות שיש להעריך בשלב discovery, ללא בחירה מוקדמת:

### ספקי מודלי הסוכנים
- Anthropic models/documentation: https://docs.anthropic.com/
- OpenAI models/documentation: https://platform.openai.com/docs/models
- מדיניות הפרויקט אינה מניחה שמות מודלים שלא הופיעו בפועל בסביבה; בכל run נשמר model ID מדויק.
- ההעדפה ל-Opus 5 במשימות 3D היא החלטת routing פנימית המבוססת על ניסיון המשתמש, ותיבדק מול benchmark של הפרויקט.

### Temporal
https://temporal.io/
https://docs.temporal.io/

מתאים ל-workflow ארוך, retries, durable state ו-compensation. בחירה חזקה ל-production.

### Prefect
https://www.prefect.io/
https://docs.prefect.io/

מתאים ל-data/ML workflows, retries ו-observability. קל יותר ל-MVP.

### LangGraph
https://github.com/langchain-ai/langgraph
https://langchain-ai.github.io/langgraph/

מתאים ל-agent state graphs ו-human-in-the-loop, אך אין להשתמש בו לבדו כ-durable GPU job system בלי persistence ותפעול ברורים.

המלצה ראשונית:
- Prefect או Temporal עבור workflow durable.
- agent layer מצומצם מעליו.
- לא לבנות orchestrator שמבוסס רק על chat loop.

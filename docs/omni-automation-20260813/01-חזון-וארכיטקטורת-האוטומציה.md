# PanoWorld Automation — חזון וארכיטקטורת האוטומציה

## מטרת המסמך
לתאר מערכת שמקבלת תוכנית רצפה ותמונת רפרנס עיצובית, מכינה באופן מבוקר את כל קלטי PanoWorld, מריצה את המודל על שרת H200 ומבצעת בקרת איכות. המערכת מיועדת תחילה להדמיות קונספטואליות; היא אינה תחליף לתכנון אדריכלי או הנדסי מאושר.

> **עדכון תפעולי 2026-08-13:** מסמך זה מתאר את המוצר המלא. האוטומציה הנוכחית מוגבלת למסלול WP0–WP6 המקומי שב־[מסמך 10](10-תוכנית-האוטומציה-המפורטת-WP0-WP6.md); אין ממנו היתר ל־H200/GPU/cloud/remote או ‏G7/G8. PLAN-003 הוא Geometry מקומי אפשרי, אך אינו נכלל אוטומטית ב־WP0–WP6.

## מסקנה מרכזית
אוטומציה גבוהה אפשרית, אך לא באמצעות LLM יחיד. הסוכן הראשי מתזמר כלים ייעודיים ודטרמיניסטיים: parser לתוכניות, מנוע גאומטריה, Blender/BlenderProc, מחולל פנורמת התחלה, PanoWorld ובקרות QA.

נוסחת העבודה:

```text
Floor plan + style reference
→ validation
→ floorplan parsing
→ normalized geometry graph
→ deterministic 3D shell
→ camera planning
→ RGB/depth/extrinsics rendering
→ style specification
→ source panorama
→ PanoWorld package
→ H200 inference
→ geometry/style/consistency QA
→ human approval
```

## מה ניתן לבצע אוטומטית

### אוטומציה גבוהה
- קליטת PDF/JPG/PNG/DWG/DXF ושמירת גרסה מקורית.
- OCR של מידות ושמות חדרים.
- זיהוי קירות, חדרים, דלתות וחלונות בתוכנית נקייה.
- יצירת גרף חדרים ופתחים.
- בניית white model בסיסי.
- הצבת מצלמות לפי כללים.
- רינדור `place_image`, עומק ו-extrinsics.
- יצירת map JSON ומבנה תיקיות PanoWorld.
- הרצת jobs, retry, logging וכיבוי שרת GPU.
- בדיקות טכניות וגאומטריות.

### אוטומציה חלקית
- תיקון קווים שבורים ותוכניות לא סטנדרטיות.
- הסקת scale כאשר אין מידות.
- מדרגות, מפלסים, קירות אלכסוניים ופתחים מורכבים.
- יצירת פנורמת 360° עקבית מתמונת סגנון רגילה.
- בחירת ריהוט הנראה נכון מכל זווית.
- תיקון חוסר עקביות בין פנורמות.

### דורש אישור אנושי
- סתירות במידות או מידע חסר.
- גובהי תקרה, דלתות וחלונות שלא מופיעים בתוכנית.
- קירות מבניים ואילוצים הנדסיים.
- אישור ה-white model לפני שימוש ב-GPU יקר.
- אישור פנורמת ההתחלה והעיצוב הסופי.
- כל תוצר שנועד לבנייה, רישוי או כתב כמויות.

## רמת אוטומציה צפויה
הערכה הנדסית, לא benchmark של PanoWorld:

| סוג קלט | אוטומציה אפשרית | הערה |
|---|---:|---|
| CAD/BIM נקי, מידות וגבהים | 85%–95% | עדיין נדרש QA אנושי |
| PDF/JPG נקי עם מידות | 70%–85% | נדרשת בדיקת scale ופתחים |
| סריקה ישנה/ללא scale | 40%–65% | הרבה הנחות ותיקונים |
| מודל אדריכלי לביצוע | לא ניתן להבטיח | נדרש איש מקצוע |

## חומרי קלט

### חובה
- תוכנית רצפה מקורית.
- יחידות וקנה מידה או לפחות מידה אחת ידועה.
- תמונת רפרנס עיצובית.
- הצהרה אם המטרה קונספטואלית או מדויקת.

### רצוי מאוד
- DWG/DXF/IFC במקום raster.
- גובה תקרה.
- עובי קירות.
- גובה ורוחב דלתות וחלונות.
- כיוון צפון ומיקום חלונות.
- רשימת חדרים.
- מגבלות שאסור לשנות.
- מספר תמונות סגנון לחדרים מסוגים שונים.

## חוזי הביניים
כל שלב חייב לכתוב artifact קריא למכונה עם schema וגרסה.

1. `project_manifest.json` — קלטים, יחידות, hash וגרסאות.
2. `floorplan_parse.json` — פוליגונים, קירות, פתחים, טקסט ו-confidence.
3. `scene_geometry.json` — מודל גאומטרי מנורמל במטרים.
4. `assumptions.json` — כל ערך שהמערכת הניחה.
5. `camera_plan.json` — נקודות מבט, גובה, orientation וקשרים.
6. `style_spec.json` — צבעים, חומרים, תאורה ושפה עיצובית.
7. `panoworld_manifest.json` — מיפוי מלא לקלטי PanoWorld.
8. `run_manifest.json` — מודלים, seeds, config, זמני ריצה ו-hashes.
9. `qa_report.json` — ציוני geometry/style/consistency והחלטה.

### 1. Orchestrator Agent
- מחזיק state machine וקובע מי רשאי לעבוד.
- אינו מעבד גאומטריה בעצמו.
- מוודא שחוזי הקלט/פלט עברו validation.
- פונה לאדם רק בהחלטה אמיתית.

### 2. Intake Agent
- שומר originals ללא שינוי.
- מפיק checksum ומטא-דאטה.
- מסווג CAD לעומת raster.
- פותח blocker אם אין scale.

### 3. Floorplan Vision Agent
- OCR, segmentation וזיהוי רכיבים.
- מפיק `floorplan_parse.json` עם confidence לכל ישות.
- אינו סוגר פערים ללא רישום הנחה.

### 4. Geometry Agent
- ממיר את הפלט למודל טופולוגי סגור.
- יוצר קירות, רצפה, תקרה ופתחים דרך Blender Python.
- מפיק `.blend`, GLB ו-`scene_geometry.json`.

### 5. Geometry Reviewer Agent
- בודק שטחים, חפיפות, קירות פתוחים ופתחים לא חוקיים.
- משווה חזרה לתוכנית המקורית.
- דורש אישור אדם כאשר confidence נמוך.

### 6. Camera Planning Agent
- מציב מצלמות במרכזי חדרים, מעברים וסמוך לפתחים.
- מונע camera-wall collision.
- מפיק `camera_plan.json` וקשרים בין viewpoints.

### 7. Render Agent
- מפעיל BlenderProc/Blender headless.
- מפיק לכל viewpoint: `place_image.png`, `place_depth.png`, `place_depth_scale.txt`, `extrinsics.txt`.
- מוודא התאמה פיקסל-לפיקסל בין RGB לעומק.

### 8. Style Agent
- מנתח את תמונת הרפרנס.
- מפיק `style_spec.json` עם palette, materials, lighting, density ו-negative constraints.
- מסמן אילו החלטות אינן ניתנות להסיק מתמונה אחת.

### 9. Source Panorama Agent
- יוצר פנורמת התחלה מעוצבת בעזרת geometry/depth/style.
- מריץ וריאציות ומדרג אותן.
- דורש אישור אדם לפני הרצת הבית המלא.

### 10. Packaging Agent
- יוצר `map_panoworld*.json` ומבנה `viewpoints`.
- בודק schemas, dimensions, file existence ו-matrices.
- מפיק package immutable עם hash.

### 11. PanoWorld Runner Agent
- מעלה package לשרת H200.
- מריץ קודם smoke test ברזולוציה נמוכה.
- רק לאחר gate מפעיל full pipeline.
- מוריד outputs ומכבה את השרת.

### 12. QA Agent
- בדיקות גאומטריה, סגנון, עקביות בין מבטים ו-artifacts.
- יוצר evidence ו-retry request ממוקד.
- אינו מאשר על סמך התרשמות מילולית בלבד.

### 13. Human Approval
שלוש נקודות אישור מינימליות:
1. geometry approved.
2. source panorama approved.
3. final outputs approved.

## State machine

```text
NEW
→ INGESTED
→ INPUT_VALIDATED
→ FLOORPLAN_PARSED
→ GEOMETRY_BUILT
→ GEOMETRY_REVIEW
→ GEOMETRY_APPROVED
→ CAMERAS_PLANNED
→ CONTROL_ASSETS_RENDERED
→ STYLE_SPEC_READY
→ SOURCE_PANO_READY
→ SOURCE_PANO_APPROVED
→ PANOWORLD_PACKAGE_READY
→ H200_SMOKE_PASSED
→ FULL_GENERATION_COMPLETE
→ QA_REVIEW
→ APPROVED / REWORK / BLOCKED
```

אין מעבר state בלי artifact, validation וראיה.

## עקרונות בטיחות ואמינות
- גאומטריה נוצרת בסקריפטים דטרמיניסטיים, לא בקליקים חופשיים של LLM.
- Blender MCP משמש לתיקון חריגים, לא לייצור סדרתי.
- כל הנחה נרשמת; אסור להסתיר hallucination.
- outputs immutable לפי run id.
- secrets נשמרים מחוץ לריפו.
- H200 מופעל רק לאחר מעבר gate מקומי.
- כל retry משנה פרמטר אחד או כולל הסבר מפורש.
- תוצר קונספטואלי מסומן ככזה.

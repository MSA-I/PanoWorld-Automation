# תוכנית בנייה מפורטת לפי שלבים

## יעד
לבנות מערכת H200-ready שממירה floorplan + style reference ל-package מאומת של PanoWorld, מריצה אותו מרחוק ומחזירה outputs עם evidence.

## שלב 0 — Baseline וחוזים

### לבנות
- `project_manifest` עם IDs, input hashes, units ו-goal.
- JSON schemas לכל artifact.
- state machine וקודי שגיאה.
- fixtures מתוך סצנות הדוגמה של PanoWorld.
- validator שקורא package תקין ומציג errors מפורטים.

### בדיקות
- schema validation לכל fixture.
- rejection של missing scale, malformed matrix ו-missing file.
- golden test מול demo package.

### Gate
- כל החוזים versioned.
- אין שדות עמומים כמו `data` או `result`.
- demo package עובר validator.

## שלב 1 — Intake ו-Input QA

### לבנות
- upload/copy service ששומר original immutable.
- PDF rasterizer.
- metadata extractor.
- OCR adapter.
- detector ל-scale, units ומידות.
- `assumptions.json` ו-`input_quality_report.json`.

### כללים
- אין לשנות original.
- כל עיבוד derivative מקבל hash.
- confidence מתחת לסף יוצר human task.

### Gate
- התוכנית ניתנת לפתיחה.
- units ו-scale ידועים או סומנו כחסם.
- אין secrets/PII מיותר ב-logs.

## שלב 2 — Floorplan Parsing

### לבנות
- interface אחיד ל-raster parser ול-vector parser.
- CubiCasa adapter או baseline חלופי.
- OCR-to-dimension linker.
- vectorization של walls, rooms, doors, windows.
- normalized coordinate transform למטרים.
- `floorplan_parse.json` ו-SVG overlay לביקורת.

### בדיקות
- precision/recall על fixtures מסומנים.
- closed room polygons.
- door-on-wall constraint.
- dimension consistency.

### Gate
- כל רכיב כולל source coordinates, confidence ו-provenance.
- overlay מאפשר לאדם לראות בדיוק מה זוהה.

## שלב 3 — Geometry Compiler

### לבנות
- graph-to-walls compiler.
- floor/ceiling extrusion.
- door/window boolean operations.
- configurable defaults לגבהים ועובי.
- Blender Python runner headless.
- exporters ל-BLEND, GLB ו-`scene_geometry.json`.

### בדיקות
- mesh manifold ככל האפשר.
- אין קירות באורך אפס.
- אין rooms חופפים.
- שטח החדרים מול שטח התוכנית בטולרנס מוגדר.
- snapshot renders להשוואה.

### Gate אנושי
- top-down overlay ו-3D preview מאושרים.
- כל default מופיע ב-assumptions.

## שלב 4 — Camera Planner

### לבנות
- room-center candidate generation.
- corridor and doorway candidates.
- collision avoidance.
- coverage scoring.
- graph connectivity.
- conversion ל-4x4 extrinsics.
- `camera_plan.json` ו-map JSON draft.

### בדיקות
- כל camera בתוך free space.
- camera height valid.
- room coverage threshold.
- adjacent views share doorway/overlap.

### Gate
- אין מצלמה בתוך wall/door/window.
- כל חדר יעד מכוסה או מסומן כ-excluded.

## שלב 5 — Control Asset Rendering

### לבנות
- BlenderProc scene loader.
- equirectangular rendering adapter.
- depth and scale writer.
- deterministic render config.
- output naming לפי PanoWorld.

### Outputs
לכל viewpoint:
- `place_image.png`
- `place_depth.png`
- `place_depth_scale.txt`
- `extrinsics.txt`

### בדיקות
- dimensions זהים ל-config.
- depth אינו ריק/NaN.
- RGB/depth alignment.
- repeatability עם אותו seed/config.

### Gate
- control asset validator ירוק בכל viewpoint.

## שלב 6 — Style Understanding

### לבנות
- image quality checks.
- VLM adapter.
- palette extraction.
- material taxonomy.
- lighting and density descriptors.
- `style_spec.json` עם confidence ו-negative constraints.

### בדיקות
- schema validation.
- deterministic normalization של שמות חומרים.
- rejection של reference שאינו פנים בית.

### Gate אנושי
- style board/spec מאושר.

## שלב 7 — Source Panorama

### לבנות
- provider interface: mock/local API/cloud model.
- conditioning על place image + depth + style.
- multi-candidate generation.
- scoring לפי geometry adherence ו-style similarity.
- provenance של model/seed/prompt.

### Gate אנושי
- פנורמת התחלה אחת מאושרת.
- אין פתחים חדשים הסותרים geometry.

## שלב 8 — PanoWorld Packager

### לבנות
- directory builder.
- `map_panoworld*.json` generator.
- manifest, checksum ו-config generator.
- package validator.
- immutable archive.

### בדיקות
- round-trip unpack/validate.
- every map node has directory.
- every viewpoint has required files.
- matrices and image sizes valid.

### Gate
- package hash קבוע.
- validation report ללא errors.

## שלב 9 — Remote H200 Runner

### לבנות
- provider-neutral interface.
- create/start/stop job.
- secure upload/download.
- progress heartbeat.
- timeout/cancel/retry.
- cost and GPU telemetry.
- guaranteed shutdown in finally path.

### סדר ריצה
1. upload.
2. low-resolution smoke test.
3. validate outputs.
4. full run.
5. download outputs/evidence.
6. terminate server.

### Gate
- no orphan GPU instance.
- logs, config, model hashes ו-runtime נשמרים.

## שלב 10 — QA

### Geometry QA
- silhouettes מול white model.
- doorway consistency.
- depth discontinuities.
- camera trajectory validity.

### Visual QA
- style similarity.
- cross-view object/material consistency.
- seam/artifact detection.
- room identity preservation.

### Policy
- retry ממוקד עם reason code.
- maximum retry budget.
- human escalation לאחר הסף.

## שלב 11 — Dashboard ופיקוח

### לבנות
- project list.
- state timeline.
- artifacts preview.
- assumptions review.
- approve/reject controls.
- agent activity ו-cost.
- blockers and decisions.
- run comparison.

### Gate
משה יכול לענות בכל רגע על:
1. מה הושלם?
2. איזו ראיה מוכיחה זאת?
3. מה פעיל עכשיו?
4. מה חסום ולמה?
5. מה הפעולה הבאה?
6. כמה זמן/עלות הושקעו?

## אסטרטגיית ענפים וסוכנים
- branch/worktree אחד לכל PLAN, לא לכל סוכן.
- ownership בלעדי לקבצים.
- producer כותב contract לפני consumer.
- orchestrator בלבד ממזג.
- כל merge דורש tests, diff review ו-evidence.
- migrations ו-schemas משתנים סדרתית.
- כל PLAN נועל provider, model ID, effort ו-fallback לכל סוכן.
- artifact קריטי מקבל review מספק אחר כאשר הדבר אפשרי.

## Definition of Done לכל שלב
- code + tests.
- docs ו-schema.
- successful run על fixture.
- failure tests.
- evidence path.
- review עצמאי.
- handoff ל-consumer.
- no unresolved critical blocker.

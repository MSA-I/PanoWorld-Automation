# מדיניות ניתוב מודלים ומאמץ — DeepSeek דרך OpenRouter

## סטטוס וסמכות

- Policy ID: `MODEL-ROUTING-v3-OPENROUTER-DEEPSEEK`.
- סטטוס: `READY FOR ACTIVATION — TOOL-CALL PROBE BLOCKED`.
- תחולה: כל PLAN, agent, review ו־run עתידי בחלק 1 המקומי.
- רישומי מודלים היסטוריים ב־evidence, handoffs ו־PLANs שהושלמו אינם משוכתבים.

## Gateway ומודלים מותרים

| Gateway | Model ID מקובע | תפקיד |
|---|---|---|
| `openrouter` | `deepseek/deepseek-v4-pro-0813` | תכנון, coding, tests, debugging, spatial/3D, security ו־review |
| `openrouter` | `deepseek/deepseek-v4-flash-0731` | reporting, formatting, state וקישורים בלבד |

כללים:

1. `OPENROUTER_API_KEY` נשמר מחוץ לריפו.
2. אין OpenRouter Auto Router, ‏`latest`, model fallback או provider fallback.
3. requested ו־returned model חייבים להיות זהים למזהה המקובע.
4. Flash אינו מכריע contract, security, geometry או gate.
5. OpenRouter הוא gateway בלבד; המודל המבוקש הוא DeepSeek.
6. tool calling חייב לעבור probe חי לפני activation.
7. `json_object` מאושר; `json_schema` קשיח אינו נתמך בנתיב שנבדק ואינו דרישת activation.

## ביקורת עצמאית

```text
Pro author session
→ deterministic tools/tests
→ Pro reviewer session נפרד, read-only first
→ bounded rework
→ fresh verification
→ automatic gate decision
```

Pro→Pro הוא same-provider session separation, לא cross-provider. Model output אינו evidence.

## Full Part 1 delegated authority

לאחר activation יחיד של משה:

- Pro רשאי לתכנן, לממש, לבדוק, לבקר, לתקן, ליצור checkpoint, למזג מקומית ולהמשיך ל־PLAN הבא.
- בחירה פתוחה מקבלת את ברירת המחדל המומלצת של ה־orchestrator, עם ADR, rationale ו־rollback.
- אין עצירת אישור שגרתית בין PLAN-002, ‏PLAN-003 ושאר שלבי חלק 1.
- שער חזותי/גאומטרי נסגר אוטומטית רק בצירוף metrics, artifacts, tests ו־review session נפרד.
- threshold או acceptance criteria אינם מוחלשים כדי להתקדם.

## Circuit breakers בלבד

עוצרים ומדווחים רק כאשר:

- auth, model identity או tool calling אינם תקינים.
- חסר קלט מהותי שלא ניתן להסיק בבטחה.
- rights/privacy/security blocker מהותי.
- בדיקה דטרמיניסטית נשארת אדומה לאחר bounded rework.
- הפעולה דורשת H200/GPU/cloud/remote, production או הוצאה מעבר לתקציב המאושר.
- נדרשת פעולה הרסנית או בלתי־הפיכה ללא rollback.

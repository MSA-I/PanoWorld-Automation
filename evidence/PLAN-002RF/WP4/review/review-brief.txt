## What was implemented

Deterministic CPU-only, no-OCR, no-learned-model recognition of a supported
clean raster floorplan into `floorplan_parse` 1.2.0 (`source_class: raster_auto`):

1. Intake + containment + canonical decode (fail-closed before pixel allocation).
2. Thresholding (global Otsu + separability gate) + connected-component labelling.
3. Line/arc voting (2-parameter Hough + physical-line clustering; Kasa circle fit
   for the bounded arc) + stroke thickness recovery.
4. Opening motif classification (door/window/passage per WP0 §4.1: gap + jamb
   ticks + leaf/glazing/nothing).
5. Two-anchor scale validation (median residual + disagreement) from the
   hash-bound manifest.
6. Fail-closed refusals: low-contrast, clutter-over-band, unexplained ink,
   over-segmentation (`RASTER_OVERSEGMENTED`), unsupported format, missing/oversized.
7. FX1-truth scorer (exact-by-key via the frozen WP1 evaluator) + deterministic SVG.

## Honest state (not a claim of acceptance)

The pixel-recognition extraction does NOT yet converge to the exact 9-wall /
6-opening / 3-room / 1-arc frozen-truth envelope on the single real fixture
(`fx1.png`): Hough over-segmentation produces many collinear-fragment walls and
the opening motifs are partially conflated with wall ink. The engine therefore
DETECTS this (`RASTER_OVERSEGMENTED`) and emits ZERO geometry — the correct
fail-closed behavior — rather than emitting a manufactured partial plan (W-17).

The ≥29/30 clean-emit acceptance gate (AT-07) requires the R0=30 corpus, which
does not exist in this repository (n=1 fixture). U-2/U-3/U-4/U-5 remain BLOCKED;
AT-21 (blind truth) has no realised labeler output. These are human-gated
prerequisites, not technical failures; this WP blocks on them rather than
fabricating accuracy.

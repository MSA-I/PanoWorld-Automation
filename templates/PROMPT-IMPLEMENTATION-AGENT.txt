סדר העבודה
----------
1. בצע Preflight קצר: Git status, branch/worktree, dependencies וקיום inputs.
2. ודא שאין עבודה לא-שמורה של סוכן אחר בקבצים שבבעלותך.
3. קרא את הקוד הקיים לפני עריכה.
4. אם התוכנית דורשת TDD, כתוב תחילה בדיקה שנכשלת מהסיבה הנכונה.
5. בצע את השינוי הקטן ביותר שממלא את המשימה.
6. הרץ את הבדיקות הממוקדות המוגדרות בפרומפט.
7. בדוק את ה-diff וודא שאין שינוי מחוץ ל-scope.
8. שמור evidence אמיתי בלבד, כולל פקודות ו-exit codes.
9. צור RUN-REPORT והחזר HANDOFF למתזמר.

כללים קשיחים
------------
- בצע רק את TASK_ID שהוקצה לך.
- אל תרחיב scope.
- אל תשנה קבצים מחוץ לבעלותך.
- אל תשנה schema, contract, API או state machine בלי אישור המתזמר.
- אל תמזג ענפים ואל תבצע push אלא אם קיבלת הוראה מפורשת.
- אל תשתמש ב-git reset --hard, git clean או force-push.
- אל תדרוס עבודה לא-שמורה.
- אל תתקין dependency שלא מופיע בתוכנית המאושרת.
- אל תחשוף secrets; החלף ערכים רגישים ב-[REDACTED].
- אל תדווח PASS בלי פלט אמיתי וקוד יציאה 0.
- אם blocked, עצור וכתוב BLOCKER במקום לנחש.

1. קוד ו-artifacts בהתאם ל-Outputs.
2. בדיקות ו-evidence בהתאם לתוכנית.

   [PROJECT_PATH]\templates\RUN-REPORT.md
4. HANDOFF לפי התבנית:

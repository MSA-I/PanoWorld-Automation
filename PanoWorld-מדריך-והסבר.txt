PanoWorld — מדריך, דרישות חומרה והסבר על חומרי הקלט
=====================================================

תאריך בדיקה: 05.08.2026
ריפו: https://github.com/jjrCN/PanoWorld
מודלים: https://huggingface.co/JiaJinrang/PanoWorld
נתונים: https://huggingface.co/datasets/JiaJinrang/PanoWorld

הערה: המסמך נכתב לאחר בדיקת הריפו, קובצי ההתקנה, הקונפיגורציות, סקריפטי האימון וה-inference, רשימת המודלים ב-Hugging Face ומבנה הדוגמאות. לא בוצעה התקנה ולא הורד שום מודל.


1. מהו PanoWorld?
==================

PanoWorld הוא מימוש רשמי של המאמר:
"PanoWorld: A Generative Spatial World Model for Consistent Whole-House Panorama Synthesis".

המערכת מיועדת לייצר פנורמות 360 מעלות עקביות של בית שלם, ולא רק תמונה בודדת של חדר. היא משלבת שני חלקים:

1. PanoWorld-LRM — בונה זיכרון תלת-ממדי מפורש מסוג 3D Gaussian Splatting ‏(3DGS) מתוך כמה תצוגות פנורמיות.
2. PanoWorld 2D Generator — מבוסס Qwen-Image-Edit ו-LoRA, ומייצר את הפנורמות הבאות תוך שימוש בזיכרון החזותי, בגאומטריה ובתמונת הסגנון.

התוצרים האפשריים:
- פנורמות 360° של נקודות מבט שונות בבית.
- עקביות יחסית בין חדרים ונקודות מבט.
- רינדורים מנקודות מבט חדשות.
- קובצי PLY של 3DGS לפתיחה ב-SuperSplat או SIBR Viewer.
- תמונות ביניים, מפות עומק ורינדורים של הזיכרון התלת-ממדי.


2. האם כל המודלים שוחררו?
=========================

כן — כל חמשת רכיבי המודל המופיעים בנתיבי ברירת המחדל של ה-inference זמינים בפומבי ב-Hugging Face ואינם gated:

- ckpt_panoworld_lrm_1024_512.pt
- ckpt_panoworld_lrm_2048_1024.pt
- Qwen-Image-Edit-2509 המלא
- pytorch_lora_weights.safetensors — ה-LoRA של PanoWorld 2D Generator
- Qwen-Image-Lightning-4steps-V2.0-bf16.safetensors

הגודל הכולל של ריפו המודלים הוא כ-68.7GB עשרוניים, שהם כ-64GiB.

מודלי בקרה חיצוניים מורדים בנפרד באמצעות הסקריפט של הפרויקט:
- PanoSAMic
- Segment Anything
- MoGe
- Mask2Former
- MMDetection ו-panopticapi

אלה מודלים וקוד של צדדים שלישיים, אך הסקריפט מפנה למקורות ציבוריים.

מה עדיין לא שלם:
- נתוני ההערכה של RealSee3D זמינים.
- נמצאו 39 סצנות 3D-FRONT מעובדות ב-Hugging Face.
- לא נמצאו שם סצנות אימון מעובדות של RealSee3D.
- ה-README עדיין מציין שהנתונים המעובדים המלאים של RealSee3D ו-3D-FRONT ישוחררו בהמשך.

מסקנה: אפשר להריץ inference בעזרת המודלים הציבוריים, אבל עדיין אי אפשר להבטיח שחזור מלא של כל האימון המקורי בעזרת הנתונים הציבוריים בלבד.

למרות שה-README מכנה את הקוד PanoWorld-v1.0, בעת הבדיקה לא היו tag או GitHub Release רשמיים; הקוד נמצא ישירות בענף main ועודכן לאחרונה.


3. סביבת ההתקנה המתאימה
========================

הסביבה המומלצת:
- Ubuntu 22.04, Linux x86_64
- Python 3.10
- PyTorch 2.6.0
- CUDA 12.4
- GPU של NVIDIA

לא מומלץ לבצע התקנה מקורית על Windows, משום שהפרויקט כולל wheel מוכן של MMCV עבור:
- Linux x86_64
- Python 3.10
- PyTorch 2.6
- CUDA 12.4
- glibc 2.31
- GPU kernels עבור SM80/SM90

יש אי-התאמה קטנה בתיעוד: ה-README מזכיר גם CUDA 12.1, אבל requirements.txt מתקין PyTorch cu124 וה-wheel המצורף של MMCV נבנה ל-CUDA 12.4. לכן יש להעדיף CUDA 12.4.


4. איזה שרת וכמה כרטיסים?
=========================

המלצה להרצת ה-full pipeline ללא מאבק בזיכרון:
- Ubuntu 22.04
- GPU אחד מסוג NVIDIA H200 עם 141GB VRAM
- 32–64 vCPU
- לפחות 128GB RAM
- לפחות 250GB NVMe לניסוי
- עדיף 500GB אם שומרים תוצאות רבות, 3DGS ונתוני ביניים

אפשר לשכור שרת כזה אצל כל ספק ענן שמציע H200. הספק פחות חשוב מהמפרט.

מספר כרטיסים ל-inference:
- כרטיס H200 אחד.
- סקריפט ה-inference הרשמי משתמש כברירת מחדל ב-CUDA_VISIBLE_DEVICES=0.
- שני כרטיסי 80GB אינם הופכים אוטומטית ל-160GB משותפים. הקוד אינו מפצל את ה-inference ביניהם כברירת מחדל.

צריכת הזיכרון שפורסמה בריפו:
- LRM, תצוגה אחת, 1024x512: כ-6.1GB
- LRM, תצוגה אחת, 2048x1024: כ-18.8GB
- LRM, 8 תצוגות, 1024x512: כ-27.5GB
- LRM, 8 תצוגות, 2048x1024: כ-108.4GB
- LRM, 12 תצוגות, 1024x512: כ-40.3GB
- LRM, 12 תצוגות, 2048x1024: OOM
- PanoWorld-DiT: כ-46.7GB

אפשרויות זולות יותר:
- LRM בלבד ב-1024x512: כרטיס 48GB יכול להספיק; A100/H100 80GB בטוח יותר.
- Full pipeline מצומצם: ניתן לנסות A100/H100 80GB עם רזולוציה נמוכה יותר, פחות תצוגות ו-CPU offload.
- כרטיס 24GB מתאים לכל היותר לניסויי LRM קטנים של מעט תצוגות. הוא אינו בחירה טובה ל-full pipeline.
- ה-wheel המצורף של MMCV אינו מותאם ל-SM89 של RTX 4090, ולכן ייתכן שיידרש build ידני גם אם הזיכרון מספיק לחלק מהפעולות.

אימון:
- סקריפטי אימון PanoWorld-LRM מוגדרים כברירת מחדל ל-8 GPUs ומשתמשים ב-DDP.
- המלצה לאימון LRM: ‏8x A100 80GB, ‏8x H100 80GB או ‏8x H200.
- אפשר להגדיר NUM_GPUS קטן יותר, אבל יהיה צורך להתאים batch size ו-gradient accumulation והאימון יהיה ארוך יותר.
- אימון LoRA של ה-2D Generator מוגדר כברירת מחדל ל-GPU אחד, batch size 1 ו-gradient accumulation 4. מומלץ לפחות A100/H100 80GB, ועדיף H200 למרווח.
- לא מומלץ כרגע לשכור שמונה GPUs לאימון מלא לפני שהנתונים המעובדים המלאים ישוחררו.


5. התקנה — כאשר יוחלט לבצע אותה
================================

שכפול הריפו ויצירת סביבה:

    git clone https://github.com/jjrCN/PanoWorld.git
    cd PanoWorld

    python3.10 -m venv .venv
    source .venv/bin/activate

    python -m pip install --upgrade pip
    python -m pip install -r requirements.txt

הורדת המודלים לתיקיות ברירת המחדל:

    hf download JiaJinrang/PanoWorld \
      --include "model_ckpt/*" \
      --local-dir .

הכנת מודלי הבקרה החיצוניים:

    bash panoworld_2d_generator/models/control_models/prepare_control_models.sh

הרצת LRM בלבד:

    bash scripts/infer_lrm_1024_512.sh

או:

    bash scripts/infer_lrm_2048_1024.sh

הרצת ה-full pipeline:

    bash scripts/infer_panoworld.sh

הפעלת מציג הפנורמות:

    bash scripts/visualize_panoworld.sh \
      examples/full_pipeline_demo_datas/scene0000/viewpoints


6. האם תוכנית רצפה ותמונת רפרנס מספיקות?
=========================================

התשובה הקצרה: לא. לא לפי ה-pipeline ששוחרר בריפו.

תוכנית רצפה רגילה כקובץ PDF/JPG ותמונת רפרנס של עיצוב אינן מספיקות כקלט ישיר. הריפו אינו כולל כלי מלא שהופך אוטומטית תוכנית רצפה דו-ממדית לכל נתוני הגאומטריה והמצלמות הנדרשים.

חשוב להבין: המערכת אינה קוראת תוכנית רצפה רגילה וממציאה ממנה לבדה את כל הבית. היא מצפה שכבר יהיו קיימים תיאור גאומטרי, נקודות מבט, תנוחות מצלמה, תמונות מעטפת ומפות עומק.

לכל סצנה נדרש בפועל:

1. מפת קשרים בין נקודות המבט
   - קובץ JSON כמו map_panoworld0.json.
   - הוא מגדיר נקודת התחלה ואילו נקודות מבט יש לייצר ממנה.
   - בדוגמה הוא נראה בערך כך:

        {
          "0000": ["0001", "0008", "0011"]
        }

2. תיקייה לכל נקודת מבט
   - לדוגמה viewpoints/0000, viewpoints/0001 וכן הלאה.

3. תנוחת מצלמה לכל נקודת מבט
   - extrinsics.txt
   - מטריצה שמגדירה מיקום וכיוון של המצלמה במרחב.

4. פנורמת מעטפת/white model של הגאומטריה
   - place_image.png
   - זו אינה תוכנית הרצפה; זהו רינדור פנורמי מתוך מודל גאומטרי של החדר/הבית.

5. מפת עומק של אותה נקודת מבט
   - place_depth.png
   - place_depth_scale.txt

6. פנורמת התחלה מעוצבת או reference style
   - בדוגמאות קיימים קבצים כמו:
     panoImage_2048_franch.png
     panoImage_2048_simple.png
     panoImage_2048_chinese.png
   - הפנורמה הזו משמשת גם כנקודת התחלה וגם כהכוונת סגנון.

7. לפי המסלול, ייתכן שיידרשו גם:
   - panoImage_2048.png
   - depth_image.png
   - transforms.json
   - תמונות perspective ומפות עומק נוספות, בעיקר ל-LRM ולאימון/הערכה.

הקובץ topdown_labeled.png שמופיע בדוגמאות אינו מספיק לבדו, ולא נמצא בריפו כלי שמקבל אותו או תוכנית רצפה רגילה ומייצר אוטומטית את כל place_image, place_depth, extrinsics ומבנה ה-map.


7. מה צריך להיות בידיים לפני שמקימים שרת?
=========================================

לניסוי ראשון עם הדוגמאות של הפרויקט:
- לא צריך להכין בית משלך.
- הריפו כבר כולל שלוש סצנות דוגמה עם מבנה הקלט הנדרש.
- צריך רק שרת מתאים, הקוד, המודלים וה-control models.

כדי להריץ על דירה משלך צריך להכין מראש:

א. תוכנית רצפה עם מידות אמיתיות
- קנה מידה.
- מידות קירות, פתחים, דלתות וחלונות.
- רצוי DWG/DXF/CAD/BIM ולא רק צילום של תוכנית.

ב. מודל גאומטרי בסיסי של הדירה
- אפשר ליצור ב-Blender, SketchUp, Revit או כלי CAD/3D אחר.
- אין חובה שהמודל יהיה מעוצב; הוא יכול להיות white model, אבל המבנה והמידות צריכים להיות נכונים.

ג. בחירת נקודות המבט
- מיקום וגובה מצלמה לכל פנורמה.
- כיוון ו-extrinsics לכל נקודה.
- בדוגמאות גובה המצלמה הוא בסביבות 1.35 מטר, אבל יש להתאים לבית.

ד. רינדור גאומטרי לכל נקודת מבט
- place_image.png — פנורמת מעטפת/white model.
- place_depth.png — מפת עומק תואמת.
- place_depth_scale.txt — קנה המידה של העומק.

ה. מפת קשרים בין נקודות המבט
- קובצי map JSON שמגדירים את סדר ההתקדמות בין הנקודות.

ו. תמונת סגנון
- עדיף פנורמת 360° של חדר בעיצוב הרצוי.
- תמונת השראה רגילה עשויה לדרוש קודם יצירת פנורמת התחלה מתאימה בעזרת מודל image-to-image אחר.
- ה-README עצמו מציין שאפשר להשתמש במודלי image-to-image אחרים כדי ליצור פנורמת התחלה בסגנון חדש.

ז. מקום אחסון
- כ-64GiB למודלים המרכזיים.
- מקום נוסף לסביבה, control models, קלטים, תוצאות וקובצי 3DGS.
- 250GB הוא מינימום סביר לניסוי; 500GB נוח יותר.


8. תהליך עבודה פשוט לדירה חדשה
===============================

1. לקחת תוכנית רצפה מדויקת עם מידות.
2. לבנות ממנה מודל 3D בסיסי של הקירות, הדלתות והחלונות.
3. להציב נקודות מצלמה בכל החדרים והמעברים.
4. לרנדר לכל מצלמה פנורמת white model ומפת עומק.
5. לייצא את תנוחות המצלמות בפורמט extrinsics המתאים.
6. להכין map JSON שמחבר בין נקודות המבט.
7. להכין פנורמת התחלה מעוצבת בסגנון הרצוי.
8. לסדר את הקבצים במבנה viewpoints של PanoWorld.
9. להריץ תחילה LRM ב-1024x512.
10. לאחר אימות הגאומטריה, להריץ את ה-full pipeline.
11. לבדוק את הפנורמות ואת ה-3DGS ולתקן נקודות מבט או גאומטריה לפי הצורך.


9. סיכום פשוט
==============

אם יש בידך רק:
- תוכנית רצפה של דירה;
- תמונת השראה של עיצוב;

זה עדיין לא מספיק להרצה ישירה.

חסר שלב הכנה משמעותי: להפוך את תוכנית הרצפה למודל גאומטרי, להגדיר מצלמות, ולייצר לכל נקודת מבט פנורמת מעטפת ומפת עומק. רק לאחר מכן PanoWorld יכול להשתמש בתמונת הסגנון כדי לייצר פנורמות עקביות של הבית.

הדרך הקלה להתחיל היא להריץ תחילה את סצנות הדוגמה שמגיעות עם הריפו על H200 אחד. אם הן עובדות ואיכות התוצאה מתאימה, אז לבנות pipeline מקדים שממיר את הדירות שלך לפורמט הקלט הנדרש.


10. הערות רישוי
================

- קוד GitHub מסומן Apache 2.0.
- כרטיס המודל ב-Hugging Face מסומן MIT.
- Qwen ומודלי הבקרה כפופים לרישיונות שלהם.

לשימוש ניסויי זה בדרך כלל מספיק, אבל לפני שימוש מסחרי יש לבצע בדיקת רישיונות מסודרת.
